The volatile Keyword in Embedded C

A comprehensive reference for Principal/Staff Engineer firmware interviews — covering the C standard, compiler behavior, hardware interactions, and pitfalls in multi-core/RTOS systems.

1. What volatile Means (C Standard)

Declaring a variable volatile instructs the compiler that its value may change at any time without any action being taken by the code the compiler can see. Per C11 §6.7.3: every access to a volatile object is treated as a visible side effect and must not be optimized away, reordered relative to other volatile accesses, or cached in a register.

One-line rule: volatile prevents the compiler from caching a variable in a register or eliminating/reordering its reads and writes. It does not provide atomicity or memory ordering across cores.

2. When to Use volatile

  • Memory-mapped I/O registers — hardware can change bits independently of CPU writes.
  • ISR-shared variables — a flag set inside an ISR and polled in the main loop.
  • Peripheral status/data registers — e.g., UART RX FIFO, DMA descriptor status word.
  • Spin-wait / busy-poll loops — prevents the compiler from hoisting the condition out of the loop.
  • setjmp / longjmp targets — locals that must survive a non-local jump must be volatile.

3. Classic MMIO Example

/* Without volatile: compiler may read status once and loop forever
   or optimize the write out entirely */
#define UART_BASE   0x40011000
#define UART_SR     (*(volatile uint32_t *)(UART_BASE + 0x00))
#define UART_DR     (*(volatile uint32_t *)(UART_BASE + 0x04))
#define TX_EMPTY    (1u << 7)

void uart_putc(char c) {
    while (!(UART_SR & TX_EMPTY))  /* polls hardware register each iteration */
        ;
    UART_DR = c;
}

4. ISR-Shared Flag Pattern

volatile bool rx_ready = false;   /* set in ISR, polled in task */

void UART_IRQHandler(void) {
    rx_buf[rx_idx++] = UART_DR;
    if (rx_idx == MSG_LEN)
        rx_ready = true;           /* compiler must emit a real store */
}

void process_task(void) {
    while (!rx_ready)              /* compiler must re-read each iteration */
        ;
    handle_message();
    rx_ready = false;
}
Interview trap: volatile bool guarantees visibility on a single-core MCU because there is only one memory master. On a multi-core SoC (e.g., dual-core ARM Cortex-M or MIPS) you additionally need a memory barrier (__DMB() on ARM) or an atomic operation to ensure cache coherency and ordering.

6. volatile in DMA and Cache-Coherent Systems

On a cached core (Cortex-A, MIPS M-class with cache), a DMA peripheral writes directly to DRAM. Marking the DMA descriptor/buffer as volatile alone is insufficient — the CPU data cache may return a stale value. The correct pattern:

/* 1. Invalidate cache lines covering the DMA buffer before reading */
SCB_InvalidateDCache_by_Addr((uint32_t *)dma_buf, DMA_BUF_SIZE);

/* 2. Now read the buffer; volatile ensures no extra compiler caching */
for (int i = 0; i < n; i++)
    process(((volatile uint8_t *)dma_buf)[i]);

7. const volatile — Read-Only Hardware Registers

/* Status register: CPU reads it, hardware updates it; CPU must not write */
#define SPI_SR  (*(const volatile uint32_t *)0x40013008)

uint32_t status = SPI_SR;  /* read is emitted; write attempt = compile error */

8. Common Pitfalls (Interview Focus)

  • Pointer-to-volatile vs volatile-pointer: volatile uint32_t *p means the data is volatile; uint32_t * volatile p means the pointer itself is volatile. In MMIO you almost always want the former.
  • Struct of volatile members vs volatile struct: Making an entire struct volatile forces volatile access on every member; if only one field is hardware-updated, mark only that field to avoid unnecessary barriers.
  • Compiler optimizations not covered: Link-time optimization (LTO) may still reorder non-volatile accesses around volatile ones; use explicit barriers where ordering with non-volatile state matters.
  • Over-use penalty: Every volatile read/write is a memory access — never declare a high-frequency local computation variable volatile without reason; it degrades performance.
