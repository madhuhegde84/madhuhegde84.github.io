Stack Implementation using Array

A complete reference for firmware/embedded DSA interviews covering LIFO principles, O(1) operations, memory efficiency, and embedded system use cases.

1. What is a Stack?

A stack is a linear data structure that follows the LIFO (Last-In-First-Out) principle: the last element added is the first one removed. Think of a stack of plates — you can only add or remove from the top.

Core principle: Array-based stacks use the array's end as the "top" for efficient O(1) push/pop operations, making them ideal for embedded firmware with constrained memory.

2. Core Structure

A stack maintains three key components:

  • int *arr — Pointer to the fixed-size array (allocated at creation).
  • int capacity — Maximum number of elements the stack can hold.
  • int top — Index of the current top element. Initialized to -1 for an empty stack.

3. Key Operations

Push (Insert)

  • Check overflow: If top == capacity - 1, stack is full.
  • Insert: arr[++top] = x; — pre-increment top, then store.
  • Time complexity: O(1)

Pop (Remove)

  • Check underflow: If top == -1, stack is empty.
  • Remove: return arr[top--]; — return current top, then post-decrement.
  • Time complexity: O(1)

Peek (Top)

  • Return top element without removing: return arr[top];
  • Check empty: Ensure top != -1 before accessing.
  • Time complexity: O(1)

isEmpty / isFull

  • isEmpty(): returns top == -1
  • isFull(): returns top == capacity - 1

4. C Implementation (Firmware-Style)

#include <stdio.h>
#include <stdlib.h>

typedef struct {
    int *arr;
    int capacity;
    int top;
} Stack;

Stack* createStack(int cap) {
    Stack* s = (Stack*)malloc(sizeof(Stack));
    s->capacity = cap;
    s->arr = (int*)malloc(cap * sizeof(int));
    s->top = -1;
    return s;
}

void push(Stack* s, int x) {
    if (s->top == s->capacity - 1) {
        printf("Stack Overflow\n");
        return;
    }
    s->arr[++s->top] = x;
}

int pop(Stack* s) {
    if (s->top == -1) {
        printf("Stack Underflow\n");
        return -1;  /* or use error code */
    }
    return s->arr[s->top--];
}

int peek(Stack* s) {
    if (s->top == -1) {
        printf("Stack is empty\n");
        return -1;
    }
    return s->arr[s->top];
}

int isEmpty(Stack* s) {
    return s->top == -1;
}

int isFull(Stack* s) {
    return s->top == s->capacity - 1;
}

void freeStack(Stack* s) {
    free(s->arr);
    free(s);
}

7. Firmware/Embedded Use Cases

  • Function call stack: MCU call stacks are array-based (hardware SP register points to stack array in SRAM).
  • RTOS task stacks: FreeRTOS/Zephyr allocate fixed-size stack arrays per task; overflow = stack corruption.
  • Expression evaluation: Parsing UART commands or evaluating postfix expressions in limited RAM.
  • Undo buffers: Storing state snapshots (e.g., register config backups) in firmware state machines.
  • DMA descriptor rings: Fixed-size circular buffers (variant of stack) for packet handling in WLAN MAC layers.

8. Interview Traps and Edge Cases

  • Overflow/Underflow: Always validate bounds before push/pop. In real firmware, overflow may trigger hard faults.
  • Initialization: top = -1 for empty; top = 0 with size counter is an alternative pattern (state clearly in interviews).
  • Memory alignment: On ARM Cortex-M, ensure stack pointer is 8-byte aligned per AAPCS (compiler handles this, but interview question bait).
  • Re-entrancy: Array stacks are not thread-safe. ISR + main loop access requires volatile + disable IRQ or mutex.
  • Stack vs Heap: Embedded C prefers stack arrays (static or auto) over heap (malloc) to avoid fragmentation — mention this trade-off.
